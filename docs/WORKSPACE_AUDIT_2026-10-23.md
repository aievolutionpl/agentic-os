# Workspace audit — 2026-10-23

Scope: the existing Electron application, using isolated local profiles and deterministic provider fixtures. This audit covers the user journey and selected accessibility checks. It does not certify WCAG compliance or live provider availability.

## Findings fixed

- **High — conversation composer could leave the viewport.** The old viewport subtraction did not include the new quota strip. Active conversations now use the remaining flex space; the transcript scrolls while the composer remains available. Verified at desktop widths by `qa:harness` and responsive scenarios in `qa:workbench`.
- **High — conversation search was hidden with the old history panel.** History is now available on demand, including search, without restoring a permanently expanded second sidebar. Existing draft, attachment, rename and transcript-copy flows remain intact.
- **Medium — selected project identity could be lost after path normalization.** Chat creation now retains the explicitly selected project ID even when the stored folder spelling differs from its canonical path. Added a regression test, including `/.` path spelling.
- **Medium — memory inspector overflowed the graph.** Desktop details now scroll within the graph; narrow screens retain a document-flow inspector. The UI test asserts its bounds.
- **Medium — low-contrast states.** Darkened warning text in light themes and strengthened the expanded More menu label. Measured solid-surface contrast checks now pass.
- **Verification — obsolete navigation selectors and indefinite animation waits.** Updated UI journeys to use the top theme selector, settings dialog, project tree and expandable More navigation. Added the five-palette suite to both Windows and Linux CI. Animation settling has a bounded wait.

## Validation and limits

Local checks: build, typecheck, lint (no errors; 43 existing warnings), release audit, smoke, qa:tools, qa:workspace, qa:harness, qa:workbench, qa:premium (including Harness Studio), qa:calm, and the seven schedule/project regression tests. PR CI is the authority for the complete cross-platform test and packaging result.

Contrast assertions cover text whose background can be resolved as solid paint. Opaque surfaces stop ancestor traversal because hidden gradients do not affect them. Complex gradients/glass are explicitly outside that calculation and receive palette checks and visual review instead. Keyboard, labels and reflow were sampled; a screen-reader audit remains outstanding.

Scheduled jobs require the desktop app to be running. They currently perform read-only analysis. Subscription percentages, API balances, context-window size and measured tokens are distinct quantities; missing provider data must stay unknown. The conversation starters are prompt templates, not a guarantee that the selected provider supports images or 3D generation.

## Five recommended improvements, in implementation order

1. **Actionable results inbox.** Combine waiting approvals, failed jobs and completed artifacts into one prioritized list. Extend the existing task/approval system with a single result view: outcome, changed files, test evidence, review/apply/rollback. Inspiration: [Linear Inbox](https://linear.app/docs/inbox) and [Cursor review](https://cursor.com/docs/agent/review). Acceptance: every pending action opens its exact task/run; completed work never looks like work still in progress. First phase: surface existing state, no new agent orchestration.
2. **Provider health and quota detail.** Keep the top strip compact; clicking a provider opens remaining windows, reset time, freshness, source and a useful recovery action. Add opt-in low-limit notifications and avoid double-counting shared OpenRouter balances. Separate subscription capacity from session/context usage. [Claude's guide](https://support.claude.com/en/articles/14552983-models-usage-and-limits-in-claude-code) makes this distinction explicit. Acceptance: stale, missing, zero and shared-pool states are separately tested; no invented token counts.
3. **Explainable project memory.** Add a local graph for the selected project/note, backlinks and an explanation of which notes were supplied to a particular answer. Move technical paths to Details; expose source, age and editable summary first. Add merge/duplicate review without automatic deletion. Inspiration: [Obsidian local graph](https://github.com/obsidianmd/obsidian-help/blob/master/en/Plugins/Graph%20view.md). Acceptance: every edge has a real provenance source, and editing memory cannot cross project boundaries.
4. **Reliable ScheduleJob editor.** Add edit, weekdays, explicit time zone, next-run preview, bounded retries for transient failures, and links from failures into the results inbox. Keep retries idempotent and never replay work after uncertain completion. Inspiration: [n8n error workflows](https://github.com/n8n-io/skills/blob/main/skills/n8n-error-handling-official/references/ERROR_WORKFLOWS.md). Acceptance: test DST changes, restart during execution, unavailable provider and quota exhaustion; no retry storm. OS wake-up remains a separate opt-in feature.
5. **Artifact-first workspace.** Open generated pages, images and 3D assets beside the conversation with a common preview/export panel. Add actual image input only to adapters that support it; present unavailable capabilities clearly. Extend the existing project browser and task handoff instead of building another chat surface. Inspiration: [Cursor agent tools](https://cursor.com/docs/agent/overview). Acceptance: a website-from-photos task goes from supported attachment to reviewed output with a reproducible result, while unsupported providers offer a clear alternative.

## Delivery sequence

- Stabilization: merge this audited baseline after green CI and installer verification.
- First increment: improvements 1 and 2, using existing task and quota data. They make daily operation easier to understand without expanding autonomy.
- Second increment: improvements 3 and 4, focusing on provenance and unattended reliability.
- Third increment: improvement 5, gated on real provider capabilities and safe preview isolation.

These are proposals, not claims that all five have already been implemented. Ship each increment with one end-to-end acceptance journey before starting the next.
